# Habitat-HM3D 中 VLN 原始任务与动作空间复现规划

## 目标

在 Habitat-HM3D 中先完成 VLN 原始任务契约和动作空间的可重复复现，建立一个可信的 baseline。当前阶段不加入 3D Gaussian Map、空间智能记忆或新的端到端改进。

核心原则：先复现“论文原始任务如何定义、观测如何输入、动作如何产生、指标如何计算”，再讨论方法改动。

## 重要边界

- HM3D 场景数据由用户提供或在确认后配置；不自动下载大型数据集。
- 不把真实终点坐标、最短路径、全局位姿、Nav2 路径或 SLAM 结果注入策略输入。
- 不把 Habitat 中的候选动作直接误称为小车的连续底盘控制。
- 不在本阶段修改 Habitat-Lab 和 Habitat-Baselines 底层实现。
- 不运行长时间、多回合或高精度评测；先做配置检查、单 episode dry run 和短 smoke test。
- 所有实验配置、日志和结果使用新的输出目录，不覆盖历史结果。

## 复现对象

### 任务层

首先确认采用的 Habitat 任务契约：

- 场景：HM3D；
- 任务：视觉语言导航的连续环境版本，优先核对 R2R-CE 或论文实际使用的任务定义；
- 输入：自然语言指令、当前视觉观测、允许的历史信息；
- 输出：论文原始动作空间中的下一步动作和停止动作；
- 评测：成功率、路径长度、SPL，以及论文明确要求的其他指标。

需要特别记录：`3D Gaussian Map with Open-Set Semantic Grouping for Vision-Language Navigation` 的公开实验使用 R2R、R4R、REVERIE 等 benchmark。若 HM3D 只是本地复现环境，必须单独记录“论文原始 benchmark”和“HM3D 适配实验”的差异，不能把适配结果写成论文原始复现结果。

### 动作层

第一阶段保持原始导航动作空间，逐项确认：

- 前进或移动动作的定义；
- 左转、右转或视角动作的定义；
- 候选 waypoint 或候选节点的来源；
- 回溯动作是否存在、何时可用；
- `[STOP]` 的触发条件；
- 动作执行步长、角度和连续环境中的实际运动效果。

本阶段不把离散/高层 waypoint 动作直接替换为 `v, omega`。后续若接入小车，再单独建立 waypoint-to-velocity adapter，并把它作为新的实验条件记录。

## 阶段任务

### 阶段 0：环境和数据前置检查

- 确认 `habitat_vlm` 环境、Python 版本和 Habitat-Sim 版本；
- 确认 HM3D 场景路径、语义/导航网格文件和许可证状态；
- 确认任务 JSON、指令字段、场景 ID 和 split 字段；
- 只检查文件和配置，不启动长时间仿真。

验收：能够用一条明确命令检查环境、场景和任务配置是否存在，并输出版本和路径摘要。

### 阶段 1：单 episode 任务复现

- 加载一个 HM3D 场景和一个 episode；
- 打印指令、场景 ID、起点和任务字段；
- 获取 RGB、深度和必要的传感器元数据；
- 执行一条人工指定的最短动作序列或安全 smoke-test 序列，仅用于验证环境动作接口；
- 记录每一步动作、观测尺寸、episode 是否结束和停止原因。

验收：单 episode 可以稳定 reset、step、获取观测、执行动作和结束；不依赖额外的终点捷径。

### 阶段 2：原始动作空间复现

- 对每个原始动作建立动作名称、参数、执行效果和终止条件表；
- 确认候选 waypoint/节点是否由环境提供、由导航图生成，或由模型预测；
- 确认 `[STOP]` 是否是策略动作，而不是外部评测强制终止；
- 保存一条 episode 的动作轨迹和观测摘要。

验收：动作空间可以被独立解释，并能由 smoke test 证明每个动作确实对应预期运动。

### 阶段 3：最小 baseline

- 先使用随机或规则策略验证 episode 流程和指标计算；
- 再接入论文或现有代码中的最小策略接口；
- 固定随机种子、split、传感器配置、最大 episode 步数和停止规则；
- 只运行极短 smoke test，确认日志结构和指标字段。

验收：baseline 能输出完整的 episode 日志，指标计算不报错；暂不追求论文数值复现。

### 阶段 4：短评测与差异记录

- 在小规模、明确数量的 episode 上运行；
- 对照论文原始任务定义、数据集、动作空间和指标；
- 记录 HM3D 适配带来的差异，例如场景、指令、相机、导航网格和动作执行方式；
- 将“已复现”“待核对”“与原论文不同”分开记录。

验收：形成一份可审计的复现报告，而不是只给出一个成功率数字。

## 每个 episode 必须记录

- episode ID、scene ID、split；
- 原始指令；
- 观测类型和尺寸；
- 策略动作；
- 动作执行后的位姿只作为评测日志保存，不作为主策略输入；
- 是否停止以及停止原因；
- 是否成功、路径长度和失败原因；
- 配置文件、随机种子和代码版本。

## 复现完成标准

只有同时满足以下条件，才认为“HM3D 原始任务和动作空间复现完成”：

1. HM3D 场景和任务 episode 可以稳定加载；
2. RGB/深度观测字段和尺寸已核对；
3. 原始动作空间每个动作都有明确解释和 smoke-test 证据；
4. `[STOP]`、回溯和 waypoint 行为已核对；
5. 最小 baseline 能完成 reset/step/结束/日志/指标闭环；
6. 论文原始 benchmark 与 HM3D 适配实验的差异已记录；
7. 没有把外部位姿、终点坐标、最短路径或 Nav2 信息输入主策略；
8. 实验结果和历史日志没有被覆盖。

## 后续接口

完成上述复现后，再单独讨论：

- 原始离散动作如何适配连续 `v, omega, stop`；
- 3D Gaussian Map 作为空间表示时输入策略的哪些信息；
- 空间记忆是否替代或补充历史观测；
- 如何设计 R2R-CE/HM3D 上的公平对照和消融实验。

这些属于下一阶段，不纳入本复现任务的完成标准。
